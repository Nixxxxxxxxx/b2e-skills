# Изменения

1. Опишите конкретный запрос, наблюдаемую проблему и желаемый результат без приватных данных.
2. Меняйте канонический SKILL или его reference, не собранный Markdown. Отдельный скилл нужен для самостоятельной задачи и результата, не для каждого раздела метода.
3. Сохраните границы действий, фактическую дисциплину и возможность работать без соседних скиллов. Не добавляйте общий запрет или обязательный ритуал по одному неудачному примеру.
4. Обновите версию выпуска и метаданные скиллов согласованно, выполните проверки и опишите реальный сценарий. Синтаксический тест не подтверждает полезность.
5. Публичные изменения проходят review второго человека. Не публикуйте исходные материалы, переписку, идентификаторы происхождения или личные данные — даже в описании PR.

`compatibility/1.0.5/` — неизменяемые архивы предыдущего выпуска. Новые инструкции редактируются только в `skills/`. Сборка не имеет доступа к приватным источникам и не должна его требовать.
