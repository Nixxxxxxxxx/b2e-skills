# Выпуск

Версия `2.0.0` — предварительная. Прохождение CI не разрешает публикацию.

1. Второй участник проверяет содержание, публичную безопасность и пользу; явно одобряет PR. Затем изменения с отдельными коммитами принимаются в `main`.
2. На одобренном коммите выполнить `npm test` и `npm run build`. Для повторной сборки указать новую папку: `node scripts/build.mjs /absolute/fresh/output`.
3. Сверить `dist/manifest.json`, включая SHA-256, количество скиллов и старые архивы `1.0.5`. Хеш самого манифеста фиксируется отдельно в конфигурации потребителя.
4. После разрешения владельца открыть репозиторий для публичного доступа. Создать тег `v2.0.0` на проверенном коммите и предварительный GitHub Release; загрузить `manifest.json` и все файлы из `artifacts` как assets. Их имена уникальны, структура каталога указана в манифесте.
5. В отдельном PR витрины зафиксировать репозиторий, тег и SHA-256 манифеста. Витрина загружает только этот выпуск, проверяя размер и хеш каждого файла, без слежения за `main` или `latest`.
6. Проверить локальную сборку и скачивания. Только после human review публиковать MD-витрину. Предыдущий deployment и выпуск сохраняются для отката.

Не заменять артефакты уже принятого выпуска. Исправления получают новую версию и новый review. Старые MD `1.0.5` сохраняются в истории исходного проекта; пять совместимых ZIP в этом репозитории заморожены и не становятся вторым местом редактирования.
